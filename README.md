# YoriMichi (寄り道)

> 오늘의 우연, 우리가 찾아줄게.

일본 여행하다 보면 "이제 뭐 하지?", "근처에 뭐 먹지?" 하고 지도 앱만 계속 넘기게 되는데, 그 고민을 줄여보려고 만든 웹앱입니다.
寄り道(요리미치)는 일본어로 "가는 길에 잠깐 들르기"라는 뜻이에요. 지금 있는 곳 근처의 축제·놀거리·맛집을 우연처럼 뽑아 줍니다.

- 서비스: https://yorimichi.duckdns.org
- 해커톤 Frame Zero 출품작 (주제: 일본 여행 중 불편했던 점 해결)

## 주요 기능

| 기능 | 설명 |
|---|---|
| 오늘의 우연 잇기 | 놀거리(또는 축제) → 근처 맛집으로 이어지는 코스를 불꽃 연출과 함께 뽑아 줌. 지금 문 닫은 곳은 제외 |
| 지금 근처 寄り道 | 현재 위치에서 **지금 당장** 갈 수 있는 곳 — 오늘 열려 있는 축제 + 영업 중인 놀거리를 한 화면에 |
| 주변 맛집 | 보정 평점(베이지안) 순 목록, 9개 종류 필터, 맛집 뽑기, 가게 리뷰 AI 한국어 요약 |
| 주변 축제 | 반경·기간으로 조회, 축제 뽑기, 상세(기간·지역·공식 사이트·근처 맛집/놀거리) |
| 주변 놀거리 | 신사·공원·성·박물관·전망·시장·유원지·온천 8종, 계절별 운영시간으로 "지금 영업 중" 계산, 상세 페이지 |
| 뽑기 패널 | 맛집·축제·놀거리 공통 — 제등이 켜지는 연출, 결과에서 서로 근처로 바로 이동 |
| PWA | 홈 화면에 추가하면 앱처럼 실행, 앱식 페이지 전환·스와이프 |
| 회원 | 회원가입 / 로그인 (JWT) |

## 화면 디자인

- 밤 축제(夜祭り) 테마: 남색 밤하늘, 등불 빨강, 금색, 반투명 유리 카드
- 페이지마다 다른 Three.js 3D 배경 (축제 거리, 참배길, 신사, 단풍 정원 등), 불꽃(花火) 연출은 GSAP
- 동작 줄이기 설정이 켜진 기기는 연출을 줄인 차분한 모드

## 배포 구조

`main` 푸시 → GitHub Actions(빌드·테스트, Oracle 컨테이너) → `deploy` 브랜치 → EC2가 1분마다 확인 후 Docker로 배포. 새 버전이 응답하지 않으면 직전 버전으로 자동 복구합니다.

## 실행 방법 (로컬)

### 1. DB 실행

```bash
docker compose up -d
```

로그에 `DATABASE IS READY TO USE!`가 뜰 때까지 기다린 뒤 서버를 켜야 합니다. (안 그러면 ORA-12514 남)

> `compose.prod.yaml`은 서버용입니다. 로컬에서 `-f compose.prod.yaml`로 띄우면 DB 비밀번호가 비어 `No Oracle app password found` 오류가 납니다.

### 2. 환경변수 설정

API 키는 코드에 없어서 직접 넣어줘야 합니다. 로컬에서는 프로젝트 폴더의 `.env`를 자동으로 읽습니다 (`.env.example` 참고).

| 이름 | 설명 | 필수 |
|---|---|---|
| `GOOGLE_MAPS_API_KEY` | Google Places API 키 | O |
| `GEMINI_API_KEY` | Gemini API 키 | O |
| `GEMINI_MODEL` | 기본 모델 (기본값 `gemini-3.5-flash-lite`) | |
| `GEMINI_FALLBACK_MODELS` | 실패 시 넘어갈 모델들, 쉼표로 구분 | |
| `JWT_SECRET` | JWT 서명 키 | 배포 시 O |
| `DB_URL` / `DB_USERNAME` / `DB_PASSWORD` | DB 접속 정보 | 배포 시 O |
| `CORS_ORIGINS` | 허용할 도메인 | |
| `PLACES_NEARBY_LIMIT` / `PLACES_DETAIL_LIMIT` | 하루 Places 호출 제한 (기본 200) | |
| `APP_DEV_EMAILS` | 개발자 계정 이메일(쉼표 구분). 이 계정만 mock 모드 사용 가능 | |

> DB 비밀번호, JWT 키는 로컬 개발용 기본값이 들어가 있음. 배포할 때는 반드시 환경변수로 덮어쓸 것

### 3. 서버 실행

```bash
./gradlew bootRun
```

- 웹: http://localhost:8080
- API 문서: http://localhost:8080/swagger-ui/index.html

### 테스트용 위치 고정

한국에서 테스트하면 근처에 일본 축제가 없으니까 URL 파라미터로 위치를 고정할 수 있게 해뒀습니다.

```
/?city=dotonbori                   테스트 도시로 고정
/?devLat=34.6687&devLng=135.5013   좌표로 고정
/?devLat=off                       고정 해제
```

### mock 모드 (구글 호출 0회)

개발자 계정(`APP_DEV_EMAILS`)으로 로그인한 상태에서만 켜집니다. 맛집 목록·뽑기·가게 상세·우연 잇기가 고정된 가짜 데이터로 나옵니다.

```
/?mock=1    이 탭에서 켜기 (왼쪽 아래 노란 "MOCK · 끄기" 표시)
/?mock=0    끄기
로고 2.5초 안에 5번 탭   이 기기에서 계속 켜기/끄기
```

## 트러블슈팅

**구글 리뷰 원문이 안 받아짐**
Places API에서 `reviews` 필드를 요청해도 계속 빈 값이 옴. 필드 마스크를 `*`로 바꿔도, 미국 가게로 테스트해도 똑같았음. 대신 `reviewSummary`(구글이 만든 리뷰 요약)는 내려와서, 이걸 받아서 Gemini로 장단점 / 메뉴 형태로 다시 정리하는 방식으로 바꿈. 원문이 왜 막히는지는 아직 확인 중.

**Gemini가 자주 실패함 (503, 응답 지연)**
무료 모델이라 트래픽 몰리면 503이 뜨거나 응답이 10초 넘게 걸림.
- 타임아웃 8초
- 503/429면 1.5초 쉬고 한 번 더
- 그래도 안 되면 다른 모델로 넘어가게 함 (`GEMINI_FALLBACK_MODELS`)

**특정 가게만 계속 요약 실패**
응답이 안 끝나고 타임아웃 나는 경우였음. `maxOutputTokens`로 길이를 제한하고, 실패한 결과는 10분 동안 기억해서 같은 요청을 반복하지 않게 함.
근데 이러니까 "다시 시도" 버튼도 막혀버려서 `retry=true` 파라미터를 따로 만들고 20초 쿨다운을 둠.

**같은 가게를 두 번 조회함**
상세 정보랑 요약이 각각 Places를 호출하고 있었음. 요약할 때는 캐시된 상세 결과를 재사용하도록 바꿔서 호출 수를 줄임.

**한국에서 접속하면 "근처에 축제 없음"**
일본인지 판별하는 범위를 위도/경도 사각형으로만 잡았더니 한반도가 통째로 들어가 있었음. 한반도, 제주, 울릉도, 연해주 쪽을 빼도록 수정 (쓰시마는 일본으로 남김).

**아이폰에서 페이지 이동할 때마다 위치 권한 팝업**
사파리, 카톡 인앱 브라우저는 페이지 열 때마다 다시 물어봄. 받은 위치를 15분 동안 sessionStorage에 저장해서 재사용하도록 함.

**아이폰 PWA에서 헤더가 상태바랑 겹침**
`viewport-fit=cover` + `safe-area-inset-top` 패딩으로 해결.

## 기타

- 구글에서 받은 가게 정보는 DB에 저장하지 않고 메모리 캐시만 사용 (구글 약관 때문, 장소 ID만 보관). 출처 표시 문구 유지
- 食べログ는 링크만 연결
- 비용 때문에 서버에서 Places 하루 호출 수 제한 + 30분 캐시, 넓은 검색 결과 재사용
- 축제·놀거리의 날짜, 운영시간, 요금, URL은 직접 확인된 것만 넣었고 확인 안 된 건 비워둠
